# 爆款结构迁移引擎 — 整体技术架构设计

## 一、系统定位与核心理念

一句话定义：**从爆款视频中"学会方法"，用新素材"做出新爆款"。**

系统不是简单的模板套用，而是一套具备**认知-记忆-规划-创作-迭代**能力的AI创作引擎。它能像一个成熟编导一样：看过大量爆款后形成了自己的"剪辑直觉"，拿到新素材后能快速出方案，并在过程中自主补齐不足的部分。

## 三、核心模块详细设计

### 模块1：爆款视频分析引擎（输入端）

**目标**：将一条爆款视频"读透"，输出结构化的分析报告。

```
爆款视频输入
    │
    ├──▶ 画面层分析（多模态LLM + OpenCV）
    │     ├── 镜头切分（场景切换检测）
    │     ├── 画面内容描述（商品/人物/场景/动作）
    │     ├── 光影与色调分析
    │     ├── 构图方式识别
    │     └── 转场类型识别
    │
    ├──▶ 声音层分析（ASR + 音频分析）
    │     ├── 语音转文字（台词/旁白）
    │     ├── BGM识别（风格、节奏、卡点位置）
    │     ├── 音效标注
    │     └── 情绪曲线提取
    │
    ├──▶ 字幕/包装层分析（OCR + 视觉分析）
    │     ├── 字幕样式（字体、颜色、位置、动画）
    │     ├── 标题条/卖点卡片样式
    │     ├── 贴纸/强调元素
    │     └── 封面设计特征
    │
    └──▶ 结构层抽象（LLM推理）
          ├── 脚本结构：hook → 痛点 → 展开 → 卖点 → CTA
          ├── 节奏结构：快-慢-快，高潮位置、镜头时长分布
          ├── 情绪结构：好奇→共鸣→信任→行动
          └── 包装策略：在哪里加什么、为什么加
```

**输出格式**：统一的 `VideoStructure` JSON Schema，包含时间轴对齐的多层结构信息。

### 模块2：知识沉淀系统（LLM Wiki 模式）

**核心思想**：不只是单次分析，而是把多次爆款分析的成果沉淀为可复用、可检索的知识体系。

```
知识沉淀的工作流：

  爆款视频1 ──┐
  爆款视频2 ──┼──▶ 分析引擎 ──▶ 结构化结果 ──▶ 知识提炼Agent ──▶ 入库
  爆款视频N ──┘                                         │
                                                        ▼
                                              ┌─────────────────┐
                                              │    知识库体系     │
                                              ├─────────────────┤
                                              │                 │
                                              │  📐 结构模板库   │  ← "开头3秒hook的5种经典模式"
                                              │  🎬 编辑手法库   │  ← "快切+放大+音效的冲击感技法"
                                              │  🎨 包装样式库   │  ← "竖屏卖货字幕的3种主流排版"
                                              │  🎵 节奏模式库   │  ← "前3秒快切→中间讲解→结尾加速"
                                              │  📊 案例索引库   │  ← 按品类/风格/平台索引的案例集
                                              │  🧠 规律洞察库   │  ← "美妆类爆款共性规律总结"
                                              │                 │
                                              └────────┬────────┘
                                                       │ 向量化存储 + 结构化标签
                                                       ▼
                                              ┌─────────────────┐
                                              │  向量数据库       │
                                              │  (检索增强生成RAG) │
                                              └─────────────────┘
```

**知识提炼过程**（由 Knowledge Agent 执行）：
1. 对每条爆款的分析结果做**特征提取**
2. 与已有知识做**关联匹配**——这条视频的hook手法和库里哪条类似？
3. 做**规律抽象**——"分析了50条美妆爆款后，发现前3秒必须有人脸特写"
4. 生成结构化的**知识条目**（带引用来源、适用场景、效果指标）

**检索与应用**：当用户提出新创作需求时，系统从知识库中检索最相关的结构模板和编辑手法，作为迁移的"源参考"。

### 模块3：Multi-Agent 编排层（系统大脑）

这是整个系统的核心调度层，采用 **Supervisor + Specialist Agents** 的模式，配合 **ReAct（Observe-Think-Act-Reflect）** 循环来迭代完成任务。

```
Supervisor Agent (总指挥)
│
│  负责：任务分解、Agent调度、质量把关、流程决策
│  工作模式：ReAct 循环
│
├──▶ Analyst Agent（分析师）
│     职责：调用视频分析引擎，输出结构化报告
│     工具：多模态LLM、ASR、OpenCV、FFmpeg
│
├──▶ Knowledge Agent（知识官）
│     职责：检索知识库、提炼新知识、提供迁移参考
│     工具：向量检索、LLM推理
│
├──▶ Planner Agent（编导）
│     职责：基于分析结果 + 知识库 + 用户需求，制定视频方案
│     输出：脚本大纲、分镜表、时间线草案、包装方案
│     工具：LLM推理
│
├──▶ Material Agent（素材管家）
│     职责：处理用户素材、识别缺口、制定补全策略
│     能力：素材分类、标签、质量评估、缺口映射
│     工具：多模态理解、OpenCV
│
├──▶ Creative Agent（创作师）
│     职责：执行内容生成任务
│     能力：T2I生成图片、T2V生成视频片段、文案生成、TTS配音
│     工具：Stable Diffusion/即梦、T2V模型、LLM、TTS
│
├──▶ Assembler Agent（合成师）
│     职责：调用Remotion/FFmpeg，将所有素材按方案合成为视频
│     工具：Remotion、FFmpeg
│
└──▶ Reviewer Agent（审核员）
      职责：检查生成结果质量，与原始方案做对比，提出修改意见
      工具：多模态LLM（视频结果评估）
```

**ReAct 迭代流程**：

```
一次完整的创作过程（简化示例）：

Observe: "用户上传了3张商品图 + 一段卖点文案，要参考某美妆爆款做新视频"
    │
Think: "需要先分析爆款结构，再检查用户素材是否够用"
    │
Act: 调度 Analyst Agent 分析爆款 → 得到结构报告
    │
Think: "爆款需要5个镜头段落，用户只有3张图，存在缺口"
    │
Act: 调度 Material Agent 识别缺口 → "缺少使用过程镜头、对比镜头"
    │
Think: "需要补全2个镜头，用T2I生成使用效果图 + 文案卡片替代对比镜头"
    │
Act: 调度 Creative Agent 生成补全素材 → 调度 Planner Agent 制定完整方案
    │
Act: 调度 Assembler Agent 合成视频 → 输出初版demo
    │
Reflect: 调度 Reviewer Agent 评估 → "开头节奏偏慢，建议前3秒改为快切"
    │
Act: 调度 Planner Agent 调整节奏方案 → Assembler Agent 重新合成
    │
Reflect: Reviewer Agent 评估通过 → 输出最终结果
```

### 模块4：素材缺口识别与补全系统

这是课题中最体现技术深度的部分。

```
素材缺口处理流程：

  ┌─────────────┐      ┌──────────────┐      ┌───────────────┐
  │ 目标结构需求  │  VS  │ 用户已有素材  │  =   │   缺口清单     │
  │ (Planner产出)│      │ (Material管理)│      │ (Material产出) │
  └─────────────┘      └──────────────┘      └───────┬───────┘
                                                      │
                    ┌──────────────────────────────────┤
                    ▼              ▼           ▼              ▼
              ┌──────────┐ ┌───────────┐ ┌─────────┐ ┌───────────┐
              │ 结构重排  │ │ 文案/包装  │ │ AIGC生成 │ │ 素材复用   │
              │ 降依赖   │ │  补全      │ │ 补全     │ │ 重组      │
              └──────────┘ └───────────┘ └─────────┘ └───────────┘
              
              优先级策略：结构重排 > 现有素材复用 > 包装补全 > AIGC生成
              （成本递增，优先用低成本方式解决）
```

**补全策略具体说明**：

| 策略 | 做什么 | 举例 |
|------|--------|------|
| 结构重排 | 调整段落顺序，降低对缺失镜头的依赖 | 没有"使用过程"镜头，改为"卖点图文卡+旁白"形式 |
| 现有素材复用 | 裁切、放大、重复利用、变速 | 一张商品图用不同裁切区域生成2-3个镜头 |
| 包装补全 | 用标题条、卖点卡片、动效贴纸补足 | 缺对比镜头→用"Before/After"卡片替代 |
| AIGC生成 | T2I/T2V生成缺失画面、TTS生成配音 | 生成"使用效果示意图"、生成旁白配音 |

### 模块5：结构迁移引擎（核心中的核心）

**问题**：如何把从爆款视频中抽象出的"结构"迁移到新内容上？

```
迁移的三个层次：

Level 1 — 脚本结构迁移（最容易实现）
  爆款脚本结构：hook(3s) → 痛点(5s) → 展开(15s) → 卖点(10s) → CTA(5s)
  迁移方式：保留结构框架，用LLM根据新商品/主题重新填充每段文案
  输出：新的分段脚本

Level 2 — 节奏结构迁移（中等难度）
  爆款节奏：快切(0-3s, 平均1.5s/镜头) → 慢讲(3-20s, 5s/镜头) → 快切(20-25s)
  迁移方式：保留节奏模板，将新素材映射到对应的时间槽
  输出：带时间节点的分镜表

Level 3 — 包装风格迁移（较高难度）
  爆款包装：黄色大字标题(顶部) + 白色字幕(底部) + 放大镜强调 + 闪白转场
  迁移方式：提取包装参数模板，适配新内容的文案和画面
  输出：Remotion可执行的包装配置
```

**迁移过程的关键数据结构**：

```typescript
// 爆款结构抽象
interface ViralStructure {
  id: string;
  sourceVideo: string;
  scriptStructure: ScriptBlock[];     // 脚本段落结构
  rhythmProfile: RhythmPoint[];       // 节奏曲线
  packagingStyle: PackagingConfig;    // 包装样式配置
  emotionalArc: EmotionPoint[];       // 情绪曲线
  metadata: { category, platform, performance };
}

// 迁移后的方案
interface VideoScheme {
  structureRef: string;               // 引用的爆款结构ID
  script: ScriptBlock[];              // 新脚本
  storyboard: StoryboardFrame[];      // 分镜表（含时间轴）
  timeline: TimelineTrack[];          // 多轨时间线（画面/字幕/音乐/包装）
  packaging: PackagingConfig;         // 包装方案
  materials: MaterialSlot[];          // 素材槽位（已填充/待补全）
  gaps: GapItem[];                    // 缺口列表
}
```

### 模块6：视频合成管线（输出端）

```
合成管线（Remotion + FFmpeg）：

  VideoScheme (方案JSON)
       │
       ▼
  ┌──────────────────────────────┐
  │  Remotion 渲染引擎            │
  │  ┌────────┐  ┌──────────┐   │
  │  │ 画面轨道 │  │ 字幕轨道  │   │
  │  ├────────┤  ├──────────┤   │
  │  │ 包装轨道 │  │ 音频轨道  │   │
  │  ├────────┤  ├──────────┤   │
  │  │ 转场层  │  │ 特效层    │   │
  │  └────────┘  └──────────┘   │
  └──────────────┬───────────────┘
                 │
                 ▼
          FFmpeg 后处理（编码、压缩、水印）
                 │
                 ▼
          最终视频输出 (MP4)
```

**为什么选 Remotion**：
- 用 React 组件描述视频画面，天然适合前端团队
- 支持参数化渲染，同一模板传不同数据生成不同视频
- 方便做"多版本生成"——同一方案换个配色/字体/节奏就能输出另一个版本
- 社区生态好，有现成的字幕、波形图、转场组件

## 四、整体工作流（端到端）

```
用户视角的完整流程：

Step 1: 上传爆款视频（1条或多条）
         ↓
Step 2: 系统分析并展示结构拆解结果（可视化）
         ├── 脚本结构图
         ├── 节奏曲线图
         ├── 包装要素清单
         └── 知识沉淀入库
         ↓
Step 3: 上传新素材 + 输入新主题/商品信息
         ↓
Step 4: 系统自动迁移结构
         ├── 生成新脚本方案
         ├── 生成分镜表
         ├── 识别素材缺口（高亮展示）
         └── 制定补全策略
         ↓
Step 5: 系统自主补全 + 合成
         ├── AIGC生成缺失素材
         ├── 包装元素生成
         ├── Remotion合成
         └── 输出视频demo
         ↓
Step 6: 用户可调（人机协同）
         ├── 调整hook方式/卖点顺序/包装风格/节奏
         ├── 自然语言指令："开头更抓人一些"
         └── 重新生成 → 迭代优化
         ↓
Step 7: 输出最终结果
         ├── 视频demo
         ├── 分镜/时间线可视化
         ├── 结构对比展示（爆款 vs 新视频）
         └── 知识沉淀更新
```

## 七、关键设计决策（需要你们确认）

| 决策项 | 选项A | 选项B | 建议 |
|--------|-------|-------|------|
| Agent编排方式 | LangGraph（有状态图） | 自研轻量编排（灵活） | 先自研核心流程，复杂了再上框架 |
| 视频分析粒度 | 逐帧分析（精确但慢） | 关键帧+LLM（快但粗） | 关键帧方案，性价比最高 |
| 知识库是否P0做 | 是（体现亮点） | 否（先保闭环） | Phase 1先不做，Phase 4补上 |
| Remotion vs FFmpeg | Remotion为主 | FFmpeg为主 | Remotion做合成，FFmpeg做预处理 |
| 前后端是否分离 | 分离（标准架构） | 全栈Node.js | 分离，方便Multi-Agent独立部署 |
