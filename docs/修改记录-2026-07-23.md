# 修改记录 — 2026-07-23

> 本次工作内容：知识库用户隔离——个人提炼的知识归个人（仅本人可见、可删），公共种子库共享且保护不被删改。

---

## 一、需求与根因

知识库此前是全局共享：所有用户看到同样的 52 条种子 + 所有人提炼的知识，任何人都能删任何条目（07-18 文档遗留问题 4）。目标：个人提炼的知识仅本人可见、可删。

## 二、语义设计

- **公共种子**（knowledge.json 中无归属记录的条目，当前即 k_0~k_51 共 52 条）：所有用户可见，Web 端不可删除（保护共享库）。
- **个人知识**（有归属记录的条目）：仅 owner 可见、可删；对其他用户表现为"不存在"（404，不泄露存在性）。
- 引擎 CLI 等绕过 Web 层新增的条目没有归属记录 → 自动成为公共条目（合理退化）。

## 三、关键决策：归属关系存 Web 数据库新表，引擎零改动

新增 `KnowledgeOwnership` 表（entry_id → user_id），**不**把 owner_id 写进 knowledge.json 条目。理由：

1. 引擎 `KnowledgeStore._load()` 按字段白名单构造 `KnowledgeEntry`，`_save()` 用 `to_dict()` 重写整个 JSON——条目里的额外字段会在任何一次增删后被静默抹掉；写进 JSON 必须改引擎 3 处（构造函数、`_load`、`to_dict`）。
2. 项目一贯约定"适配都在 Web 层，引擎零改动"（07-18 关键决策 1/2/4）。
3. 归属是用户概念，User 本来就在 Web DB；知识内容仍以 knowledge.json 为单一事实源（07-18 决策 5 不变）。

## 四、改动（6 个文件）

### 后端

- `db_models.py`：新增 `KnowledgeOwnership` 表（`entry_id` 主键、`user_id` 外键、`created_at`）；新表由 `create_all` 自动创建，无需 ALTER 迁移。
- `database.py`：`create_db_and_tables()` 追加 `_migrate_knowledge_ownership()`（幂等）：按提炼入库的 id 签发规则 `^k_u(\d+)_` 解析存量条目 owner 并补插归属行（当前无此类条目，迁移为 no-op，保证任何存量数据下正确）。
- `routers/knowledge.py`：
  - 新增 `_ownership_map()` / `_is_visible()`；可见规则 = 公共（无归属）或本人。
  - `GET /api/knowledge`：按可见范围过滤，每条加 `mine: bool`；`GET /api/knowledge/stats` 同样按可见范围计数。
  - `DELETE /api/knowledge/{id}`：不存在 → 404；他人私有 → 404（不泄露）；公共种子 → 403「公共知识不可删除」；本人 → 删条目 + 删归属行 + 清 demo 文件。
- `routers/genes.py`：`extract-knowledge` 在 `store.add_entry()` 后写入归属行（`KnowledgeOwnership`）。
- `routers/stats.py`：工作台 knowledge 计数改为当前用户可见范围（公共 + 我的）。

### 前端

- `Knowledge.jsx`：卡片加归属 Badge（「我的」绿色 / 「公共」灰色）；删除按钮仅在 `mine` 时渲染。
