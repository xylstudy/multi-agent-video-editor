# 修改记录 — 2026-08-30

> 本次工作内容：新增「统计洞察 / Insights」模块——跨多个已分析视频做统计挖掘，提炼可复用的剪辑结构规律（带样本量与置信度），并提供自包含 HTML 可视化报告。引擎、后端、前端三端打通。

---

## 一、需求与根因

知识库 / 基因库此前沉淀的是**单视频**的拆解结论（每个爆款一份 `analysis_result.json` 或 `analyst/` 产物）。但项目里已累计分析 11+ 条爆款，没有任何一处把"这些视频**共同**的剪辑规律"聚合出来——例如"爆款前 3 秒平均几个镜头""高频转场是什么""情绪弧线 5 段各自主导哪种情绪"。这些跨视频的统计规律才是"结构迁移"最该复用的知识，却一直散落在各份独立报告里。

目标：新增一个洞察视图，扫描所有已分析视频，输出 5 个维度的统计结论 + 置信度，并支持逐镜头轨迹 drill-down。

## 二、语义设计

- **5 维洞察**（每条带 `sample_size` 与 `confidence`，样本不足如实标注，不编造结论）：
  1. `hook` — 前 3 秒镜头数 + 主要 hook 方法
  2. `rhythm` — 镜头时长中位数/范围 + 后 1/3 段较前 1/3 是否加速
  3. `shot_types` — 镜头类型整体分布 + 前 3 镜集中度
  4. `emotion_arc` — 5 段式情绪弧线每段主导情绪 + 整体情绪基调
  5. `transitions` — 高频转场及占比
- **置信度分级**：`high`（样本 ≥5）、`medium`（≥2）、`low`（<2，标注"样本不足"）。
- **数据边界**：扫描引擎共享目录（示例/种子分析）+ **当前用户自己的**基因存储目录；不触碰其他用户的私有报告（与项目/基因隔离策略一致）。
- **报告**：自包含 HTML（内联 SVG + 原生 JS，零外部依赖，离线可打开），含总览表、逐视频镜头时间线（色块=镜头类型，点击展开推理轨迹）、情绪弧线 + 节奏强度双折线图、镜头类型/转场分布条形图。

## 三、关键决策

1. **实时挖掘，不缓存**：后端 `GET /api/insights/report` 每次请求即时重新扫描挖掘，保证新分析的视频立即出现在报告里（洞察数据量小，重算成本可接受）。`run_insight_mining.py` CLI 则把 `insights.json` + `insight_report.html` 落盘到 `data/output/`，便于离线查看。
2. **兼容新旧两种分析产物格式**：`discover_analyses()` 同时识别 `analyze_video.py` 新格式（`analysis_result.json`，单文件含 `shots[]` + `raw_structure_analysis`）与旧格式（`data/runs/*/analyst/` 下 `shot_analyses.json` + `structure_analysis.json`），统一归一化为 `VideoAnalysisData`；旧数据时间全为 0 时回退到 `raw_shot_analyses` 取时间，无有效时间则不下时间相关结论。
3. **轨迹 drill-down 取数据**：优先读 `analysis_trace.json`（含每镜 frame_paths / prompt_version / model / analysis），无轨迹则用 `raw_shot_analyses` 兜底——保证"点击时间线色块看推理轨迹"在有无轨迹文件时都有内容。
4. **用户隔离在 Web 层完成**：后端扫描根追加 `STORAGE_ROOT/users/{user_id}`，引擎与 `insight_miner.py` 保持零用户概念（延续"适配都在 Web 层"的一贯约定）。
5. **HTML 报告鉴权**：报告接口 `GET /api/insights/report` 支持 `?token=` 鉴权，前端用 `<iframe>` 嵌入，避免把 HTML 直链暴露给未登录用户。

## 四、改动（8 个文件 / 3 端）

### 引擎侧（viral-structure-engine/）

- `knowledge/insight_miner.py`：**新增**。`InsightMiner`（5 维 `mine()`）、`discover_analyses()`（多根扫描去重）、`normalize_new_format()` / `normalize_legacy_format()`（格式兼容）、`NormalizedShot` / `VideoAnalysisData` 数据类、`_confidence()` / `_fmt_counter()` 辅助。
- `insight_report.py`：**新增**。`generate_report()` 生成自包含 HTML（总览表 + 时间线 SVG + 双折线图 + 条形图），`SHOT_TYPE_COLORS` / `EMOTION_LEVELS` 配色与情绪纵向映射。
- `run_insight_mining.py`：**新增** CLI 入口。默认扫描 `data/runs` + `data/output` + 项目根 `data/output` + `web/backend/storage`，输出 `insights.json` + `insight_report.html`，并打印洞察摘要。

### 后端（web/backend/）

- `routers/insights.py`：**新增**。`GET /api/insights`（挖掘结果 JSON）、`GET /api/insights/report`（HTML 报告，`?token=` 鉴权，实时重算），`_scan_roots()` 按用户隔离扫描目录。
- `main.py`：`routers` 导入追加 `insights`，并 `app.include_router(insights.router)`。

### 前端（web/frontend/src/）

- `components/Layout.jsx`：`NAV_ITEMS` 追加「统计洞察」（`/insights`，图标 `BarChart3`），位于知识库与作品集之间。

## 六、遗留事项

- 洞察目前只统计已有分析产物，**不反向写回知识库**——"高频规律 → 自动沉淀为知识结构模板"可列为后续方向（与 07-23 遗留"生成时知识检索注入"同源）。
- `emotion_arc` 维度依赖 `emotion` 字段，部分旧格式报告缺该字段时该维度样本会被过滤（已在 finding 中标注"样本无情绪数据"）。
- 报告为每次请求实时重算，样本量极大（数百视频）时可能变慢，当前 11+ 样本规模无压力。
- 多用户场景：共享目录（示例/种子分析）对所有用户可见，仅"用户私有基因目录"按用户隔离；即洞察结论包含公共样本，符合预期。
