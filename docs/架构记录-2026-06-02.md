## 背景

爆款结构迁移引擎的代码骨架已经搭建完成，但合成环节（Assembler）过于薄弱——只做了 FFmpeg 线性拼接，完全没用到 Planner 产出的详细方案信息。

3. 重新规划 Planner → Renderer → Assembler 三层分工

## 一、合成引擎替换：Remotion

### 为什么是 Remotion

之前 Assembler 只做了一件事：按分镜顺序把素材路径收集起来，扔给 FFmpeg concat。Planner 产出的转场类型、字幕文案、Ken Burns 配置、情绪节奏……全浪费了。

Remotion 的核心优势：
- **精确到帧的控制**：每个分镜的 duration、transition、动画都由代码精确控制
- **图层叠加**：视频/图片/文字/形状可以同时叠加，不是线性拼接
- **React 生态**：字幕动画、转场效果、Ken Burns 等都是现成的 React 组件
- **LLM 友好**：组件就是代码，LLM 可以直接生成

### 实现结构

```
remotion/
├── src/
│   ├── Root.tsx                 # 入口，注册 VideoScheme 合成
│   ├── VideoScheme.tsx          # 主组件：按 Sequence 编排分镜
│   ├── types/schema.ts          # TS 类型（与 Python 模型对齐）
│   └── components/
│       ├── DynamicFrame.tsx      # 核心调度器：按名加载组件渲染
│       ├── registry.ts           # 组件注册表（内置 + 动态）
│       ├── Transitions.tsx       # 转场：cut/fade/dissolve/slide/flash_white
│       ├── KenBurns.tsx          # 图片缩放/平移
│       ├── Subtitles.tsx         # 字幕逐字动画
│       ├── TextCard.tsx          # 文字卡
│       └── AudioLayer.tsx        # BGM 音轨
├── compile_dynamic.py           # Python 编译脚本
└── src/dynamic/                 # LLM 生成的组件放在这里
```

### 如何调用

```
# Assembler 自动调用：
npx remotion render src/Root.tsx VideoScheme out.mp4 --props=input_props.json

# 失败时回退到 FFmpeg 拼接
```

## 二、核心思路：LLM 自主决定渲染

### 解决的问题

传统方案中，渲染逻辑是硬编码的：

```python
if text_card_content:
    render_text_card(...)
elif has_video:
    render_video(...)
elif has_ken_burns:
    render_ken_burns(...)
```

这行不通——LLM 产出的方案千变万化，预设组件永远追不上需求。

### 新方案

渲染策略由 LLM 逐分镜决策，路径有三条：

```
Planner 产出的方案
        │
        ▼
Renderer Agent (LLM)
        │
        ├── "auto"              → 系统自动推断（内置组件兜底）
        ├── "text_card"         → 用内置 TextCard 组件
        └── "custom:xxx"        → 从注册表加载自定义组件
                │
                ├── 已有 → 直接加载
                └── 没有 → LLM 写组件代码
                        │
                        ├── 写入 src/dynamic/comp_xxx.tsx
                        ├── esbuild 编译为 .js
                        └── 注册到组件注册表
```

### 组件注册表

内置组件和 LLM 生成的自定义组件统一注册：

| 组件名 | 来源 | 说明 |
|--------|------|------|
| `text_card` | 内置 | 全屏文字卡，打字机/淡入动画 |
| `ken_burns` | 内置 | 图片缩放/平移 |
| `subtitles` | 内置 | 字幕叠加 |
| `transitions` | 内置 | 入场转场动画 |
| `test` | 示例动态组件 | 渐变色 + 旋转文字 |
| `xxx` | LLM 生成 | 按需，随方案变化 |

## 三、三层架构重塑

### 旧的流水线

```
Planner → Creative → Assembler(FFmpeg拼接)
```

Assembler 是个空壳，Creative 的缺口识别也是断裂的。

### 新的流水线

```
Planner ──→ Renderer ──→ Creative ──→ Assembler(Remotion)
   │            │            │              │
   │ 方案+扩展    │ 渲染策略    │ 素材缺口      │ 渲染视频
   │ 字段        │ +自定义组件  │ 补全          │
   ▼            ▼            ▼              ▼
```

### 三层各司其职

| 层级 | 角色 | 做什么 | 输出 |
|------|------|--------|------|
| **Planner** | 编导 | 出结构方案，标注渲染 hint、画幅、每帧的粗剪参数 | `VideoScheme` + 扩展字段 |
| **Renderer** | 渲染工程师 | 逐帧决策渲染方式，生成缺失的 React 组件 | 更新了 `render_component` 的方案 + 编译好的组件 |
| **Assembler** | 合成师 | 接收完整方案 + 组件注册表，调用 Remotion 渲染 | `rendered_video_path` |

### Planner 新增字段

**每帧**：`render_component`、`custom_render_config`、`layers`、`canvas_width/height`、`ffmpeg_segment`

**全局**：`canvas_width/height`、`render_hints`、`render_pipeline`、`ffmpeg_timeline`

这些字段是可选的——Planner 按需输出，不输出就走默认值。

## 五、一些想法

### 关于 FFmpeg 的定位

FFmpeg 不退出舞台，只是职责收窄了。Planner 可以在方案中输出 `ffmpeg_segment` 和 `ffmpeg_timeline`，描述"把这段素材从第 3 秒剪到第 10 秒、放慢 0.5 倍速"。这些粗剪操作在素材准备阶段由 FFmpeg 执行，最终的精细编排由 Remotion 接手。也就是 `FFmpeg 做粗剪，Remotion 做精编`。

### 关于 LLM 写代码的安全性

Renderer Agent 生成的 React 组件运行在 Remotion 的沙箱环境中，权限仅限于渲染帧画面。没有文件系统访问、没有网络请求、没有系统调用。安全风险是可控的。
