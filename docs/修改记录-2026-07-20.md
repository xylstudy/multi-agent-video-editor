## 一、基因提取失败排查 + API Key 配置

### 根因

前端基因提取报"步骤 gene_extraction 执行失败，退出码 1"，逐层排查后确认为两层原因：

1. **401 Unauthorized**：数据库（testuser 账号）和 `viral-structure-engine/.env` 里的智谱 Key 都是占位符 `fake-key-test`，`analyze_video.py` 分析第一个镜头时 `raise_for_status()` 直接抛异常退出。真实 Key 从未硬编码进代码（工作区、git 历史、两个原始压缩包全部查过，均为占位符）。
2. **429 Too Many Requests**：换上真 Key 后脚本可跑通，但两个提取任务并发抢同一账号触发智谱限流；脚本自带退避重试（5s→25s），单任务慢速可完成，并发会互相拖死。

### 配置（用户提供真实 Key 后）

- `viral-structure-engine/.env`：写入真实 `ZHIPU_API_KEY`、新增 `DEEPSEEK_API_KEY`（全局兜底）
- 数据库 `apikey` 表：
  - `playtest`（测试账号，user_id=5）绑定智谱 + DeepSeek 两个 Key
  - `testuser`（user_id=2）的假智谱 Key 替换为真 Key（**必须修**：`setup_api_keys_for_user` 每次跑任务会把用户 Key 写进 .env，假 Key 会覆盖真 Key）
- 验证：智谱、DeepSeek 单独调 API 均返回 200

### Key 需求清单（代码实际使用）

| Key | 用途 | 必要性 |
|-----|------|--------|
| `ZHIPU_API_KEY`（GLM-4.6V） | 视频镜头画面分析（基因提取）、照片素材理解 | 必需 |
| `DEEPSEEK_API_KEY`（deepseek-chat） | 文本推理、端到端多智能体流水线 | 必需 |
| `ALIYUN_ACCESS_KEY_ID/SECRET` | 照片前景分割（segment_aliyun.py） | 可选 |
| `MOONSHOT_API_KEY` | 备选 LLM，仅预留 | 可选 |

语音转写走本地 whisper，无需 Key，但需 `pip install openai-whisper`（当前未装，转写自动跳过，非致命）。

## 二、Bug 修复：删除基因不取消提取进程

### 现象与根因

前端删除正在提取的基因记录后，后端 `analyze_video.py` 子进程变成孤儿继续运行（白烧 API 额度），跑完才发现 DB 记录没了报错退出。删除接口只删了 DB 行和文件，没有任何任务取消机制。

### 改动（3 个文件）

- `pipeline_runner.py`：新增子进程注册表 `_active_procs` 与 `kill_active_process(proc_key)`；`run_command` / `_run_command_sync` 增加可选 `proc_key` 参数，Popen 启动时登记、结束（finally）时注销
- `gene_worker.py`：新增 `_extraction_tasks` 任务登记表；`start_gene_extraction()`（登记 asyncio 任务，done 回调自动清理）；`cancel_gene_extraction()`（先杀子进程 `gene_{id}`，再取消 asyncio 任务）；提取调用传入 `proc_key`
- `routers/genes.py`：创建基因改走 `start_gene_extraction()`；**删除接口先调 `cancel_gene_extraction()`** 再删记录和文件

### 验证（真实链路）

用 playtest 创建基因（示例视频）→ 确认提取子进程拉起（PID 4168）→ DELETE 返回 204 → 3 秒后进程表无残留；后端日志确认"已终止子进程 → 已取消任务"。

## 三、知识库转场演示：从"示例"改为"教学"

### 问题

用户反馈演示看不出重点：硬切和淡入不仔细看看不出区别。代码层面的三个原因：

1. 转场时长按生产参数：fade/dissolve 的 overlap 仅 4 帧（0.13 秒），硬切为 0，且有 20 帧上限封顶
2. 演示照片全是北京风景照、色调相近、都带同样的 Ken Burns 缓动，A→B 内容差异小
3. 无转场点标记、无时间轴、转场只演一次

### 改动（`remotion/src/TechniqueDemo.tsx`，生产组件零改动）

- **转场放慢**：非硬切转场统一拉伸到 30 帧（1 秒），结构为 A 段 30f → 转场 30f → B 段 30f（总时长 80f → 90f，`getDemoDuration` 同步更新）
- **A/B 画面编码**：新增 `TeachScene`，A 画面蓝色调 + 圆形大字角标、B 画面橙色调 + 角标
- **底部教学时间轴**：新增 `TransitionTimeline`，`画面A(蓝) → 转场·技法名(黄，激活时呼吸高亮) → 画面B(橙)` 三段着色，白色播放头实时指示位置
- **硬切专用 `CutLoopDemo`**：A→B→A→B 循环 4 段（22/22/22/24 帧），每个切点白闪 3 帧标记，时间轴交替标注，副标题注明"无过渡直接切换 · 白闪处为切点"

### 渲染与验证

- 删除旧转场 mp4，批量重渲 **23 条全部成功**（约 4 分钟，单条约 2.5MB）
- 抽帧目检：硬切（交替时间轴）、淡入（1.5s 处明显半透明混合）、甩镜头（运动模糊峰值）、故障抖动、圆形展开，时间轴/角标/转场过程均清晰可见
- 已知特性：生产缓动曲线前快后慢（`Easing.bezier(0.16,1,0.3,1)`），部分转场（如圆形展开）动作集中在窗口前段；如需更慢可把演示窗口拉到 1.5 秒

### 后续维护

新增/修改演示仍用 `python render_knowledge_demos.py`（增量）/ `--only k_x --force`（单条重渲）。
