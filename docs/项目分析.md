### 3.2 Agent 内部机制：ReAct 循环

所有 Agent 继承自 [BaseAgent](file:///E:/py%20pbjects/video_claw/viral-structure-engine/agents/base.py)，内部运行 **ReAct 循环**：

```
Agent 被 Supervisor 调用
         │
         ▼
  ┌─────────────────┐
  │  Thought 思考    │ ← LLM 分析当前状态
  └────────┬────────┘
           ▼
  ┌─────────────────┐
  │  Action 行动     │ ← 调用一个工具（或 done）
  └────────┬────────┘
           ▼
  ┌─────────────────┐
  │  Observation    │ ← 工具返回结果
  │  观察           │
  └────────┬────────┘
           │
    任务完成？──是──→ 返回 AgentResult 给 Supervisor
          否
           │
           ▼
      回到 Thought（循环，最多 15 步）
```

核心代码逻辑（[base.py:L56-L139](file:///E:/py%20pbjects/video_claw/viral-structure-engine/agents/base.py#L56-L139)）：

```python
async def execute(self, state: dict) -> AgentResult:
    for step_idx in range(15):              # 最多 15 步
        decision = await self.llm.chat(     # 让 LLM 做决策
            decision_prompt,
            system=self.system_prompt,
            response_format="json",
        )
        action = decision.get("action")     # 工具名
        action_input = decision.get("action_input")

        if action == "done":                # 任务完成
            return AgentResult(success=True, data=..., steps=...)

        result = await self.tools[action](**action_input)  # 执行工具
        # 记录步骤，继续循环...

    return AgentResult(success=False, message="超过最大步骤数")
```

### 3.4 LangGraph 图结构

[graph/builder.py](file:///E:/py%20pbjects/video_claw/viral-structure-engine/graph/builder.py) 中定义的 LangGraph 图：

```
                    ┌───────────┐
                    │supervisor │ ◄── LLM 决定下一步
                    └─────┬─────┘
                          │
          ┌───────────────┼───────────────────┐
          │       │       │       │           │
          ▼       ▼       ▼       ▼           ▼
      analyst  material  planner  creative  assembler  reviewer
          │       │       │       │           │           │
          └───────┴───────┴───────┴───────────┴───────────┘
                          │
                is_complete? ──是──→ END
                         否
                          │
                          ▼
                    回到 supervisor
```

关键设计：每个专家节点执行完后**回到 Supervisor**，由 Supervisor **再次用 LLM 决策**下一步。不是固定 DAG，而是**动态循环**。

路由函数（[builder.py:L413-L450](file:///E:/py%20pbjects/video_claw/viral-structure-engine/graph/builder.py#L413-L450)）：

```python
# Supervisor 出边：读取 current_task.expert 决定目标节点
lambda s: s.get("current_task", {}).get("expert", "__end__")

# 其他节点出边：is_complete 则 END，否则回 Supervisor
lambda s: END if s.get("is_complete") else "supervisor"
```

## 四、共享状态 ViralEngineState

[graph/state.py](file:///E:/py%20pbjects/video_claw/viral-structure-engine/graph/state.py) 定义了 **共享黑板（Shared Blackboard）** 模式——所有 Agent 在同一块状态上读写，而非流水线传递。

```python
class ViralEngineState(TypedDict):
    """所有 Agent 共享的工作记忆 — 不是流水线传送带，是共享黑板"""

    # ===== 用户输入（只读） =====
    sample_videos: list[str]        # 爆款视频路径
    user_materials: list[dict]      # 用户素材
    target_topic: str               # 新 Vlog 主题
    target_info: dict               # 主题详情
    user_preferences: dict          # 用户偏好

    # ===== Vlog 专属输入 =====
    domain: str                     # "vlog"
    vlog_style_preference: str      # 风格偏好
    narrative_type_hint: str        # 叙事类型提示
    persona_config: dict            # 人物出镜配置

    # ===== 共享工作区（Agent 按需读写） =====
    source_structures: list         # [VideoStructure, ...] — Analyst 写入
    material_inventory: Any         # MaterialInventory — MaterialManager 写入
    scheme: Any                     # VideoScheme — Planner 写入
    knowledge_refs: list            # [KnowledgeEntry, ...] — Phase 4
    gap_report: dict                # 缺口报告 — Creative 写入
    generated_materials: list       # AI 生成的素材 — Creative 写入
    rendered_video_path: str        # 合成视频路径 — Assembler 写入
    review_result: dict             # 审核结果 — Reviewer 写入

    # ===== Agent 通信区 =====
    current_task: dict              # Supervisor 下发的任务
    last_result: dict               # 专家 Agent 上报的结果

    # ===== 流程控制 =====
    phase: str                      # init → analyst → materials → planning → gaps → assemble → review → complete
    iteration: int                  # 迭代轮次
    max_iterations: int             # 最大迭代次数（默认 3）
    is_complete: bool               # 任务是否完成
    errors: list[str]
    logs: list[dict]                # 所有 Agent 的决策日志
```

## 五、数据流（逐步骤分析）

### 核心概念：State 是共享黑板，不是流水线

```
时间线     Supervisor 黑板                 专家写入
──────    ──────────────────────────      ────────────────
T1        观察: source_structures=[]
            决策: → analyst

T2                                                      Analyst:
                                  source_structures=[VideoStructure{...}]
                                  phase="materials"

T3        观察: 有结构，material_inventory=None
            决策: → material_manager

T4                                                      MaterialManager:
                                  material_inventory={items: [...], gaps: [...]}
                                  phase="planning"

T5        观察: 有结构+素材，scheme=None
            决策: → planner

T6                                                      Planner:
                                  scheme=VideoScheme{storyboard: [...], ...}
                                  phase="gaps"

T7        观察: 有方案了，检查缺口
            决策: → creative

T8                                                      Creative:
                                  gaps=[已填充策略]
                                  generated_materials={fill_plans: [...], text_cards: [...]}
                                  phase="assemble"

T9        观察: 缺口处理完了
            决策: → assembler

T10                                                     Assembler:
                                  rendered_video_path="data/output/vlog.mp4"
                                  phase="review"

T11       观察: 视频合成完了
            决策: → reviewer

T12                                                     Reviewer:
                                  review_result={scores: {...}, total_score: 72, pass: false}
                                  iteration=1
                                  is_complete=false
                                  phase="planning"  ← 回到 planner 迭代

T13       观察: 审核没通过，iteration(1) < max_iterations(3)
            决策: → planner（迭代模式）

          ...循环...

T14       观察: 审核通过或超迭代次数
            决策: → __end__
```

### 完整流程的 LLM 调用次数估算

| 阶段 | 调用次数 | 说明 |
|------|---------|------|
| Supervisor 决策 | 6-10 次 | 每次回到 Supervisor 调一次 LLM |
| Analyst 分析 | 2 + N 次 | 1 次信息获取决策 + N 次镜头分析 + 1 次结构分析 |
| MaterialManager | 1-4 次 | 每个素材调 1 次 LLM + 1 次缺口检查 |
| Planner | 2-3 次 | 骨架提取 + 方案生成 +（可选）迭代 |
| Creative | 1-2 次 | 补全策略 +（可选）文字卡生成 |
| Reviewer | 1 次 | 8 维度审核 |
| **总计** | **约 15-30 次** | 取决于镜头数和迭代轮次 |

## 七、BaseAgent 基类解析

[agents/base.py](file:///E:/py%20pbjects/video_claw/viral-structure-engine/agents/base.py) 是整个系统的核心抽象，定义了所有 Agent 共享的 ReAct 循环模式。

### 7.1 核心数据结构

```python
# 枚举：所有 Agent 角色
class AgentRole(Enum):
    SUPERVISOR = "supervisor"
    ANALYST = "analyst"
    PLANNER = "planner"
    MATERIAL_MANAGER = "material_manager"
    CREATIVE = "creative"
    ASSEMBLER = "assembler"
    REVIEWER = "reviewer"
    KNOWLEDGE = "knowledge"

# 单步执行记录
@dataclass
class AgentStep:
    step_index: int       # 步骤序号
    thought: str          # LLM 的思考过程
    action: str           # 调用的工具名
    action_input: dict    # 工具参数
    observation: str      # 工具返回结果
    is_final: bool        # 是否是最终步骤

# 执行结果
@dataclass
class AgentResult:
    success: bool
    data: Any = None
    message: str = ""
    steps: list[AgentStep] = field(default_factory=list)
```

### 7.2 BaseAgent 抽象基类

```python
class BaseAgent(ABC):
    role: AgentRole              # 角色标识
    system_prompt: str           # 系统提示词
    tools: dict[str, callable]   # 工具名 → 工具函数

    def __init__(self, llm: Optional[LLMTools] = None):
        self.llm = llm or LLMTools()
        self._step_history: list[AgentStep] = []
        self._tool_results: dict[str, Any] = {}

    @abstractmethod
    def _build_observe_prompt(self, state: dict, history: list[AgentStep]) -> str:
        """每个 Agent 自定义：从 state 中提取当前任务上下文"""

    async def execute(self, state: dict) -> AgentResult:
        """ReAct 循环核心"""
        for step_idx in range(15):
            decision = await self.llm.chat(
                decision_prompt,            # 包含状态 + 工具列表 + 历史
                system=self.system_prompt,
                response_format="json",
            )
            action = decision.get("action")
            if action == "done":
                return AgentResult(success=True, ...)
            result = await self.tools[action](**decision.get("action_input", {}))
            # 记录步骤、继续循环...
        return AgentResult(success=False, message="超过最大步骤数")
```

```python
# 图结构定义（builder.py:L415-L450）
def build_graph():
    workflow = StateGraph(ViralEngineState)
    
    # 添加所有节点
    workflow.add_node("supervisor", supervisor_node)
    workflow.add_node("analyst", analyst_node)
    # ... 添加 material/planner/creative/assembler/reviewer
    
    # Supervisor → 专家（条件路由）
    workflow.add_conditional_edges(
        "supervisor",
        lambda s: s.get("current_task", {}).get("expert", "__end__"),
        {"analyst": "analyst", "material_manager": "material",
         "planner": "planner", "creative": "creative",
         "assembler": "assembler", "reviewer": "reviewer",
         "__end__": END}
    )
    
    # 专家 → Supervisor（条件路由）
    for node in ["analyst", "material", "planner", "creative", "assembler", "reviewer"]:
        workflow.add_conditional_edges(
            node,
            lambda s: END if s.get("is_complete") else "supervisor"
        )
    
    workflow.set_entry_point("supervisor")
    return workflow.compile()
```

## 十五、项目优势

1. **真正的 Multi-Agent** — 每个专家内部有完整 ReAct 循环（思考→行动→观察），非简单函数调用
2. **Prompt 与 Agent 解耦** — Prompt 在 `prompts/` 独立调优，不混在 Agent 代码中
3. **模型层统一** — 所有数据有 `to_dict()`，支持 JSON 序列化，跨 Agent 通信标准化
4. **新旧兼容** — 通过 `__post_init__` 自动处理 v0.1 → v0.2 的字段迁移，不破坏下游
5. **工具层可替换** — LLM 客户端通过 `LLMTools` 抽象，Doubao / GPT-4o 只改配置
6. **可解释性** — 每个 Agent 记录完整的 `AgentStep` 思考链路，存到 `state.logs`
7. **动态路由** — 不是固定 DAG，Supervisor 每次用 LLM 根据当前状态动态决策
8. **审核闭环** — 方案经过 8 维度评分，不通过可自动迭代优化

## 十六、风险与改进建议

| 风险 | 严重度 | 说明 | 建议 |
|------|--------|------|------|
| **LLM 调用成本高** | 高 | 完整流程约 30+ 次 LLM 调用，每次 Agent 内部决策都调 LLM | 缓存相似决策结果；预算约束场景用 mock 模式 |
| **Supervisor 单点依赖** | 高 | Supervisor 决策错了整套流程会偏，无校验机制 | 加入决策置信度评分；关键决策增加"二次确认" |
| **无超时处理** | 中 | 内部 15 步循环，但单步 LLM 可能卡住（超时 60s 但多次重试可能更久） | 给 execute() 加 asyncio.wait_for |
| **视频处理同步** | 中 | FFmpeg subprocess 调用是同步的，会被 asyncio 事件循环阻塞 | 用 asyncio.create_subprocess_exec 替代 subprocess.run |
| **无错误恢复** | 中 | Agent 失败后无自动重试或降级策略 | 加入 retry 装饰器 + 降级执行路径 |
| **无进度持久化** | 中 | 中断后无法从断点恢复，必须从头开始 | 引入 checkpoint 机制（langgraph 的 checkpointer） |
| **无并发分析** | 低 | 多个 sample_videos 和 user_materials 是串行处理 | 用 asyncio.gather 并行分析 |
| **OpenCV 场景检测精度** | 低 | 灰度帧差法精度有限，对渐变转场不敏感 | 可替换为 PySceneDetect 或 TransNetV2 |
| **无集成测试** | 低 | 只有单元测试（24个），缺少端到端集成测试 | 加入 mock LLM 的端到端测试 |
| **Supervisor 策略固化** | 低 | 决策逻辑是线性条件链，缺少并行派活能力 | 可扩展为"同时派发多个专家" |
