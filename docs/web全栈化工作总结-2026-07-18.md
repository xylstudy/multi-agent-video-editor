# Video Claw Web 全栈化工作总结

> 日期：2026-07-18
> 范围：`web/` 前后端从 0 到 1 + 引擎能力产品化
> 关键词：FastAPI、React、任务队列、WebSocket、视频基因、知识沉淀

---

## 一、宏观：今天要解决什么问题

项目的核心资产是 `viral-structure-engine/`——一个能拆解爆款 Vlog 结构（Hook、节奏、段落、剪辑技法）并把结构迁移到用户素材上的多智能体引擎。但它此前只有一堆命令行脚本：

- 没有用户概念，谁都能改谁的文件；
- 跑一次生成要手动敲多条命令，过程不可见；
- 每次分析产出的结构报告散落在 `data/runs/` 目录里，跑完就扔，无法复用；
- 引擎里沉淀的 52 条剪辑知识（`knowledge_db/knowledge.json`）没有任何界面能看到。

**今天的目标就是把这台"发动机"装进一辆能开的车里**：给它配上用户系统、任务队列、实时进度，并把引擎的隐藏能力（结构报告、知识库）做成可浏览、可复用的产品功能。

## 二、整体架构：三层结构

```
┌─────────────────────────────────────────────────────────┐
│  前端 React（web/frontend，Vite + Tailwind，端口 5173）  │
│  10 个页面，深色主题设计系统                              │
└──────────────────────┬──────────────────────────────────┘
                       │ HTTP /api + WebSocket（Vite 代理）
┌──────────────────────▼──────────────────────────────────┐
│  后端 FastAPI（web/backend，端口 8000）                   │
│  认证 → 项目/素材 → 任务队列 → 进度广播                   │
│  genes / knowledge / works / stats 四个产品模块           │
└──────────────────────┬──────────────────────────────────┘
                       │ 子进程调用脚本 + 进程内 import
┌──────────────────────▼──────────────────────────────────┐
│  引擎 viral-structure-engine/                            │
│  analyze_video.py / run_material_analysis.py /           │
│  run_editing_transfer.py / run_pipeline_e2e.py /         │
│  knowledge/ 知识子系统（knowledge.json 为单一事实源）     │
└─────────────────────────────────────────────────────────┘
```

关键的数据流（一次端到端生成）：

```
用户上传参考视频+照片 → 任务入队 → 素材分析 → 视频结构分析
→ （编辑迁移 或 多智能体）渲染 → 成片入库 → WebSocket 全程推送进度
```

另一条新打通的数据流（基因提取）：

```
用户上传爆款视频 → 后台 asyncio 任务跑 analyze_video.py
→ 报告存入基因库 → 可一键提炼知识入 knowledge.json
→ 创建项目时可直接选用该视频作参考（自动复制素材）
```

## 三、功能全景：从 6 页到 10 页

| 页面 | 作用 | 对应的引擎能力 |
|---|---|---|
| 工作台 `/` | 统计卡（项目/基因/知识/成片）+ 最近任务 + 新手引导 | 聚合视图 |
| 项目 `/projects` | 创建/管理生成项目，支持从基因库选参考视频 | — |
| 项目详情 | 上传素材、选步骤（端到端/仅素材/仅视频分析）、历史任务 | 各 run_*.py |
| 任务详情 | 步骤时间线、实时日志终端、进度条、视频预览、下载 | 队列 + WebSocket |
| 基因库 `/genes` | 上传爆款视频，异步提取结构基因，卡片式管理 | analyze_video.py |
| 基因报告 `/genes/:id` | Hook 策略、段落结构、节奏曲线图、包装风格、逐镜头标注 | 报告可视化 |
| 知识库 `/knowledge` | 52 条知识的类型 Tab、搜索、删除；从基因一键提炼入库 | knowledge/ 子系统 |
| 作品集 `/works` | 所有成片集中画廊，内嵌播放 + 下载 | 任务结果聚合 |
| 设置 `/settings` | 每用户独立配置智谱/DeepSeek/Moonshot Key | 引擎 .env |
| 登录/注册 | 多用户 JWT 认证 | — |

产品的完整闭环：**工作台 → 基因库（拆解爆款）→ 知识库（沉淀经验）→ 项目（迁移生成）→ 作品集（展示成果）**。

## 四、微观：各部分具体实现

### 4.1 后端（web/backend/）

**基础骨架**
- `db_models.py`：User / Project / Material / Task / ApiKey / Gene 六类实体，SQLModel + SQLite。
- `auth.py`：bcrypt 密码哈希 + JWT（7 天有效期）。
- `queue_manager.py`：单 worker asyncio 队列，进度写入 Task.logs 并经 WebSocket 广播。
- `pipeline_runner.py`：把项目素材转成引擎脚本输入，按任务类型执行对应步骤，支持端到端、仅素材分析、仅视频分析三种任务。

**四个新产品模块**
- `routers/genes.py` + `gene_worker.py`：基因的 CRUD、视频上传（含"一键用示例视频"）、报告详情、视频流播放、提炼知识入库。提取动作由独立后台 asyncio 任务执行，状态机为 `pending → analyzing → done/failed`，前端 3 秒轮询。
- `routers/knowledge.py`：每次请求重新加载引擎 `knowledge.json`（保证新提炼的知识立即可见），支持类型过滤、关键词搜索、删除。
- `routers/works.py`：聚合当前用户所有 `end_to_end + success` 任务的 mp4 成片。
- `routers/stats.py`：工作台所需的计数与最近任务。

**基因复用**
- `ProjectCreate` 新增可选 `gene_id`；创建项目时若指定基因，后端把基因视频复制为项目的 VIDEO 素材，用户只需再传照片即可开跑。

### 4.2 前端（web/frontend/）

- **设计系统**：`index.css` 定义深色设计令牌（页面底 `#0c0c14`、卡片 `#14141f`、主色 `#7c5cfc`、点缀 `#00d4ff`），`components/ui.jsx` 沉淀 Button/Card/Badge/StatusPill/ProgressBar/Field/InfoBar/EmptyState 等共享组件。
- **布局**：左侧固定边栏（Logo + 6 项导航 + 底部用户区），移动端折叠为顶部条 + 抽屉。
- **亮点组件**：
  - `StepTimeline`：按日志实时推导"素材分析→视频分析→渲染输出"各步骤状态（完成/运行中/失败），并按任务类型只显示相关步骤；
  - `LogTerminal`：mac 风标题栏 + ERR 行染红 + 新日志自动滚底；
  - 基因报告页的节奏曲线图（纯 CSS 柱状图，无图表库依赖）。
- **交互细节**：基因分析中自动 3 秒轮询、知识库搜索 350ms 防抖、卡片 hover 浮起、空状态全量覆盖。

### 4.3 引擎侧改动（保持最小侵入）

- `agents/knowledge_agent.py`：补上缺失的 `_build_observe_prompt` 抽象方法实现。
- 其余引擎脚本零改动——所有适配都在 Web 后端层完成。

## 五、关键技术决策（为什么这么做）

1. **视频分析统一走 `analyze_video.py`，不走 `run_video_analysis.py`**
   `run_editing_transfer.py` 硬编码读取 `data/runs/video_analysis_demo/analyst/shot_analyses.json`，且要求每条镜头含 `shot_index` 字段；而 `run_video_analysis.py` 经 `AnalystAgent._analyze_shot` 产出的字典没有该字段，直接跑会 `KeyError: 'shot_index'`。
   决策：Web 后端调用 `analyze_video.py`（其输出含 `raw_shot_analyses` 且带 `shot_index`），再把结果拆写到引擎约定的固定路径。引擎脚本一行未改。

2. **后端 `models.py` 改名 `db_models.py`**
   后端单文件模块 `models` 与引擎的 `models/` 包同名。当后端进程内 import 引擎的 `knowledge.store` 时，引擎内部的 `from models.knowledge import ...` 错误地命中了后端的 `models.py`，知识库 API 直接 500。
   决策：后端模块整体改名（13 个文件批量替换），把 `models` 这个顶层名字让给引擎包。

3. **基因提取走独立后台任务，不占任务队列**
   基因不隶属于任何项目（它是跨项目的可复用资产），生命周期也与生成任务不同。用独立 asyncio 任务 + Gene 表自带状态机，队列继续专职处理生成类任务，职责清晰。

4. **知识条目 ID 入库前重新签发**
   引擎 `KnowledgeStore.add_entry` 默认按 `k_{当前总数}` 分配 ID，会与既有 52 条种子（k_0 ~ k_51）冲突互相覆盖。
   决策：Web 层入库时统一改写为 `k_u{user_id}_{uuid8}` 全局唯一 ID，不动引擎的分配逻辑。

5. **知识库直连引擎 `knowledge.json`**
   不在 Web 数据库里复制一份知识（那样会产生两处事实源、需要同步）。知识库每次请求直接读引擎文件，写入也回写引擎文件，引擎流水线与 Web 界面看到的是同一份知识。

## 六、发现并修复的 bug

| Bug | 现象 | 根因 | 修复 |
|---|---|---|---|
| `KnowledgeAgent` 无法实例化 | 提炼知识必报 `Can't instantiate abstract class` | 基类抽象方法 `_build_observe_prompt` 未实现 | 引擎中补上最小实现 |
| 删除项目 500 | 带素材的项目删不掉 | SQLAlchemy 默认把子表外键置 NULL，违反 NOT NULL 约束 | 改为显式级联删除任务、素材文件、项目目录 |
| `KeyError: 'shot_index'` | 编辑迁移步骤必失败 | 两个分析脚本输出格式不一致 | 见决策 1 |
| 知识库 API 500 | `No module named 'models.knowledge'` | 后端 models.py 遮蔽引擎 models/ 包 | 见决策 2 |

## 七、验证情况（只列真实跑过的）

- **API 层**：认证、项目（含 gene_id 创建并验证素材自动复制）、素材上传、三类任务、genes 全端点、knowledge 列表/搜索/统计、works、stats、级联删除——全部 curl 验证通过。
- **UI 层**：`npm run build` 零报错；用 puppeteer-core + 系统 Chrome 对 10 个页面（含移动端抽屉、任务成功/失败/单步三种状态）无头截图逐页目检。
- **明确限制**：本环境无有效 LLM Key，基因提取与知识提炼只验证到"失败并返回中文提示"的降级路径，未产出真实 LLM 分析结果。

## 八、遗留问题与下一步

1. **配置真实 `ZHIPU_API_KEY`**（设置页或引擎 `.env`）后，需完整跑通一次"基因提取 → 端到端生成 → 成片入作品集"的全链路。
2. JWT secret 目前每次重启随机生成，旧 token 全部失效；生产环境应改为固定环境变量。
3. 任务队列为单 worker，不支持并发；多用户同时提交会排队。
4. 知识库为多用户共享且均可删改，暂无归属/权限设计。
5. 后续方向：Remotion 成片在线预览微调、基因报告的版本对比、知识库在生成时的检索注入可视化。
