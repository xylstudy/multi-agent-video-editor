## 一、修复视频无法播放（作品集 / 任务详情 / 基因库）

### 根因

前端通过 JWT `Authorization: Bearer` 头鉴权，但 `<video>` 标签和 `<a download>` 发起的请求无法携带自定义请求头，导致所有媒体端点返回 401，视频无法播放、无法下载。

### 改动

**后端**

- 新增 `web/backend/media.py`：
  - `get_current_user_media`：媒体端点专用鉴权，优先读 `Authorization` 头，缺失时回退到 `?token=` 查询参数（`OAuth2PasswordBearer(auto_error=False)`）
  - `range_file_response`：支持 HTTP Range 请求（206 Partial Content），视频可拖动进度条、断点续传；无 Range 头时回退完整 `FileResponse`；非法范围返回 416
- 改造端点（鉴权依赖换为 `get_current_user_media`，响应换为 `range_file_response`）：
  - `GET /api/tasks/{task_id}/download`
  - `GET /api/genes/{gene_id}/video`

**前端**

- `api.js` 新增 `mediaUrl(path)`：拼接 `/api{path}?token={当前JWT}`
- 接入页面：`Works.jsx`（播放 + 下载）、`TaskDetail.jsx`（结果预览）、`GeneDetail.jsx`（源视频预览）

### 验证结果

| 用例 | 结果 |
|------|------|
| 完整请求（带 token） | 200，返回完整文件 |
| Range 请求 `bytes=0-1023` | 206，精确返回 1024 字节 |
| 无效 token | 401（安全边界未放开） |
| 经 Vite 代理端到端请求 | 200 / 206 通过 |

## 二、知识库演示：52 条知识全部配上演示视频

### 需求

知识库中的知识此前只有文字描述。本次为每个知识条目渲染一段独立的技法演示短片，并在知识卡片中内嵌播放。

### 知识 → 演示映射

知识条目（`data/knowledge_db/knowledge.json`）的 `structured_data.id` 与 Remotion 渲染组件一一对应：

| 知识类型 | 数量 | 演示形式 |
|---------|------|---------|
| transition_type（转场） | 23 | A 照片 → 转场 → B 照片（复用生产 `DualTransitionLayer`） |
| effect_type（特效） | 4 | 胶片颗粒 / 变速重映射 / 运动模糊 / 强化甩镜头 |
| editing_technique（前景揭示） | 7 | 背景 + 前景分离揭示动画 |
| editing_technique（字幕样式） | 8 | 照片 + 对应字幕样式（打字机/霓虹/渐变条等） |
| packaging_style（包装风格） | 3 | 3 场景链 + 风格预设的转场/字幕/颗粒组合 |
| editing_technique（抽象原则） | 7 | 具象化演示：前3秒抓眼球（大标题+快切）、音乐卡点（含 BGM + 节拍点）、5段式情绪弧线（分段标注）、前景背景分离、速度对比、转场不重复（4 种转场连播）、胶片质感 |

### 实现

- 新建 `viral-structure-engine/remotion/src/TechniqueDemo.tsx`：
  - 通过 props（`kind` / `tech_id` / `title`）渲染 9 类演示
  - 所有场景按 1080×1920 设计坐标构建，合成注册为 540×960，`DesignFrame` 整体 `scale(0.5)`，布局与生产渲染一致、渲染速度约提升 4 倍
  - 每条演示顶部标注技法名称与类型
  - 复用生产组件：`DualTransitionLayer`（转场）、`FilmGrain`/`MotionBlur`/`useSpeedRamp`/`useWhipPanEnhanced`（特效）、`SceneSubtitle`（字幕样式，本次在 `ForegroundSplit.tsx` 中改为导出）
- `Root.tsx` 注册 `TechniqueDemo` 合成，`calculateMetadata` 按 `kind` 计算时长
- 新增 `viral-structure-engine/render_knowledge_demos.py` 批量渲染脚本：
  - 用法：`python render_knowledge_demos.py`（增量，已存在跳过）/ `--only k_0` / `--force`
  - 输出：`web/backend/storage/knowledge_demos/{entry_id}.mp4`
- **渲染结果：52 条全部成功**（单条 2~4 秒、540×960，共约 130MB，耗时约 8 分钟）

### 排障：画面下半截黑边

初版渲染中照片只显示上半截。根因：Remotion `AbsoluteFill` 是 `display:flex` 容器，其 flex 子元素（1080×1920 设计容器）因 `flex-shrink` 默认值被压缩到画布高度。修复：`DesignFrame` 内层容器加 `flexShrink: 0`。修复后全幅显示正常。

### 接口与页面

- 后端 `routers/knowledge.py`：
  - `GET /api/knowledge/{entry_id}/demo`：演示视频（Range + token 鉴权，含路径穿越防护）
  - `GET /api/knowledge`：列表项新增 `has_demo` 标记
  - 删除知识条目时同步删除对应演示视频
- 前端 `Knowledge.jsx`：知识卡片新增「播放演示」按钮，点击后才加载视频（避免整页 52 个视频并发加载），支持循环播放

### 后续维护

新增知识条目后，运行 `python render_knowledge_demos.py` 即可增量补渲染。

## 三、日常启动方式

新增一键启动脚本 `start_web.bat`（项目根目录，双击可用），或手动两条命令：

```bash
# 终端 1：后端
cd "E:\py pbjects\video_claw\web\backend"
python -m uvicorn main:app --host 127.0.0.1 --port 8000

# 终端 2：前端
cd "E:\py pbjects\video_claw\web\frontend"
npm run dev
```

浏览器访问 http://localhost:5173 。注意事项：

- 停止服务 = 关闭两个命令行窗口（或 Ctrl+C）
- 后端重启会使旧登录态失效（JWT 密钥按启动生成），需重新登录
- 端口被占用时：`netstat -ano | findstr "5173 8000"` 找到 PID 后 `taskkill /PID <进程号> /F`
- Windows 下停止 npm 任务可能残留 vite 子进程，需按 PID 手动终止
