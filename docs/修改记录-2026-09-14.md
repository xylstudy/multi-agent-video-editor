# 修改记录：高级 Remotion 动效组件库 V1

## 目标

把方案生成从简单的 `fade/slide/zoom` 升级为可复用的镜头配方，并保证方案 JSON、素材绑定、Remotion 注册和真实渲染形成闭环。

## 实施结果

| 模块 | 完成内容 |
| --- | --- |
| 高级文字 | `focus_blur_resolve`、`kinetic_warp`、`mask_reveal_up`、`rgb_glitch_text` |
| 素材编排 | `broll_stack`、`split_screen_burst`、`polaroid_collage`、`beat_montage` |
| 镜头与包装 | `parallax_photo`、`hero_push_in`、`cinematic_grain`、`neon_light_rays` |
| 高级转场 | `zoom_through`、`liquid_warp`、`chromatic_aberration` |
| 方案生成 | Planner 与 Renderer 均注入稳定组件目录，禁止为这些组件重复生成临时代码 |
| 素材绑定 | 支持从 `source_material_ids`、`material_ids` 和 `layers[].material_id` 收集多图素材 |
| 渲染稳定性 | Remotion 临时构建目录移动到项目盘，避免 C 盘空间不足；渲染后自动清理 |

## 方案 JSON 示例

```json
{
  "render_component": "custom:beat_montage",
  "transition_in": "chromatic_aberration",
  "custom_render_config": {
    "source_material_ids": ["photo_1", "photo_2", "photo_3"],
    "beat_frames": [0, 8, 17, 25],
    "accent_color": "#00d9ff",
    "intensity": 0.8
  }
}
```

`beat_frames` 是相对当前镜头的帧位置。项目当前为 30fps，例如第 15 帧约等于镜头开始后的 0.5 秒。

## 验证

- `npx tsc --noEmit`：通过。
- `pytest tests/test_motion_catalog.py tests/test_models.py -q`：18 项通过。
- Web 后端全量测试：19 项通过；前端 Vite 生产构建通过。
- 真实 Remotion 冒烟渲染：1080×1920、30fps、4.05 秒、H.264，成功输出 `advanced-motion-smoke.mp4`。

# 修改记录：任务产物同步到基因库与统计洞察

## 问题根因

参考视频分析报告原来只保存在任务目录 `projects/{project_id}/tasks/{task_id}/analysis`；基因库读取数据库 `Gene` 记录，统计洞察只扫描当前用户的 `genes` 目录。任务完成后缺少入库动作，因此两个页面都不会出现本次分析。

同时，工作台“生成成片”使用小写字符串查询枚举字段，而 SQLite 实际存储枚举名，导致成功的端到端任务仍被统计为 0。

## 修复结果

- 新增 `web/backend/gene_sync.py`，把完整的任务参考视频报告、视频副本、分析轨迹与关键帧同步到当前用户的基因目录。
- 同步后写入 `Gene` 摘要字段并回填 `Project.gene_id`；以项目关联保证重试不会重复入库。
- 新任务在视觉分析完成后立即同步；从已有基因创建的项目继续复用原基因，不产生副本。
- 服务启动时自动回填修复前已经完成、但尚未入库的历史任务。
- 统计洞察仍只扫描当前用户的基因目录，保持账号隔离，并在每次请求时实时聚合。
- 工作台成片数改用 `TaskStatus.SUCCESS` 与 `TaskType.END_TO_END` 枚举查询。

## 验证

- Web 后端全量测试：22 项通过。
- 历史任务 #1 已回填为基因 #1：15 个镜头，报告和视频文件均存在。
- 用户 3 当前统计：1 个项目、1 条基因、1 个洞察样本、1 个成片。

## 知识库同步补充

- 新增 `web/backend/knowledge_sync.py`，在基因产生后自动生成结构模板、Hook 技法、节奏模式、情绪设计、包装风格五类个人知识。
- 知识直接基于已完成的结构分析报告在本地归纳，不会额外上传完整报告，不增加 API 调用费用。
- 每条知识写入当前用户的 `KnowledgeOwnership`，继续保持账号隔离，并带有来源基因、来源用户和本地规则版本等溯源信息。
- 同一基因只提炼一次；手动点击和任务自动同步并发时也不会重复入库。
- 服务启动时会为旧版本中已完成但未提炼知识的基因自动回填。
- 用户 3 的历史基因 #1 已生成 5 条个人知识，重复同步验证为 0 条新增。

## 知识视频示例

- 复用 `viral-structure-engine/remotion/src/TechniqueDemo.tsx` 的教学型 Remotion 合成，为个人知识生成可播放的短视频示例。
- 五类自动归纳知识分别映射到结构时间轴、前三秒 Hook 快切、音乐卡点、情绪弧线和包装配方演示。
- 演示文件保存到 `web/backend/storage/knowledge_demos/{entry_id}.mp4`，知识接口返回 `has_demo=true` 后，前端卡片显示“播放演示”。
- 当前用户 3 的 5 条个人知识均已生成视频，文件大小约 2.4–5.1 MB，并已通过接口逐条校验。
